# RuProbe

Telegram-бот проверки доступности IP, доменов и диапазонов с точки наблюдения
«регион + оператор», с классификацией отказов по модели ТСПУ.

Бот не утверждает причину недоступности. Он собирает структурированные факты
набором зондов и выдаёт **вероятностную классификацию** по сработавшим
сигнатурам — потому что недоступность и «недоступность из-за ТСПУ» разные вещи,
а трафик может не доходить до фильтра вовсе.

## Состав

| Каталог | Что внутри |
|---|---|
| `agent/` | Go-зонд: сетевые пробы, HTTP-контракт, без постоянного состояния |
| `bot/` | Python: Telegram, БД, классификация, рендеринг отчётов |
| `docs/` | `tspu-model.md` — модель зондов и четыре класса отказа; `stack.md` — версии |
| `tools/` | `integration_check.py` — сквозной прогон без Telegram |
| `compose.yaml` | единственный файл развёртывания на оба сервиса |

## Запуск

```powershell
Copy-Item .env.example .env
# заполните BOT_TOKEN от @BotFather
docker compose up --build
```

Оба сервиса поднимаются на одной машине. Порт агента наружу не публикуется:
бот обращается к нему по имени сервиса внутри сети `ruprobe`.

## Запуск без Docker

Агент:

```powershell
cd agent
go run ./cmd/agent
```

Бот:

```powershell
cd bot
$env:BOT_TOKEN = "..."
$env:AGENT_URL = "http://127.0.0.1:8080"
$env:DB_PATH = "..\.tmp\ruprobe.sqlite3"
python -m alembic upgrade head
python -m ruprobe_bot.main
```

## Что можно проверять

Домен (`example.com`), адрес (`1.1.1.1`), подсеть (`192.0.2.0/29`),
диапазон (`1.2.3.4-1.2.3.20`).

Агент выполняет от десяти зондов: DNS через системный резолвер, публичный и DoH;
TCP connect с явным различением RST и таймаута; TCP по альтернативным портам;
отправку ClientHello с заданным SNI без завершения handshake; контрольную пробу
тем же адресом с другим SNI; полный TLS-handshake и HTTP; замер пропускной
способности; UDP/QUIC; ICMP; пинг соседних адресов.

## Классы отказа

| Класс | Наблюдаемая сигнатура |
|---|---|
| блокировка по адресу/порту/транспорту | SYN уходит, ответа нет; все порты недоступны; ICMP при этом отвечает |
| блокировка по признакам протокола (SNI) | SYN-ACK получен, ClientHello ушёл, дальше тишина до таймаута; тот же адрес с другим SNI отвечает |
| деградация пропускной способности | handshake проходит, короткий запрос отвечает, длинная передача «пилит» окно |
| вмешательство в разрешение имён | резолверы расходятся; NXDOMAIN, REFUSED, SERVFAIL, молчаливый drop |
| недоступность не по ТСПУ | сигнатуры не подтвердились — полноценный результат, а не «не смогли решить» |

## Проверка

```powershell
cd agent
gofmt -l cmd internal ; go build ./... ; go vet ./... ; go test ./...

cd ..\bot
python -m pytest tests -q
```

Сквозной прогон против живого агента (нужен запущенный `agent`):

```powershell
python tools\integration_check.py
```

## Границы

Техники обхода (фрагментация ClientHello, анти-DPI, туннелирование) не
реализуются: проект только наблюдает доступность. Реализация — один регион и
один оператор; мультиоператорность заложена в схему, интерфейс управления ею не
делается. Расписания и подписки: таблица заведена, планировщик вне рамок.
